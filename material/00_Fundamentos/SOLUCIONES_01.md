# Clase 1 · Soluciones explicadas

[Ejercicios](EJERCICIOS_01.md) · [Clase](CLASE_01.md)

## 1. Una compra

Entrada: precio de una lapicera = 800; cantidad = 4. Proceso: multiplicar 800 × 4. Salida: total = 3.200 pesos. Precio y cantidad son los datos conocidos; el total es el dato calculado.

## 2. Explicar una idea

Hay muchas respuestas válidas. Por ejemplo, para ordenar tres números: recibir los tres valores, compararlos, colocarlos de menor a mayor y mostrar la secuencia. Lo importante es que el problema tenga un resultado claro y que los pasos permitan alcanzarlo. Una actividad cotidiana también sirve si sus pasos son suficientemente precisos.

## 3. Responsabilidades

- Título: HTML, porque describe contenido.
- Fondo azul: CSS, porque define presentación.
- Calcular al pulsar: JavaScript, porque aplica una operación y responde a una acción.
- Campo de nombre: HTML, porque crea un control del formulario.
- Cerrar un mensaje: JavaScript puede escuchar la acción y ocultarlo. CSS puede definir su estado visual oculto. En una aplicación real, las tecnologías cooperan.

## 4. Error

Muestra 503. Debería mostrar 1.500. Se reemplaza MAS por POR en el cálculo. Sumar el precio y la cantidad mezcla dos valores que cumplen funciones diferentes; multiplicar expresa tres unidades de 500.

## 5. Petición

1. La persona pulsa «Ver productos».
2. El frontend envía una solicitud al backend.
3. El backend consulta los productos guardados.
4. El backend responde con la lista.
5. El frontend muestra la lista recibida.

Ese orden representa el caso del ejercicio. Una aplicación puede usar datos ya cargados sin repetir siempre la consulta.

## 6. Caso límite

Con cantidad cero, el resultado de la multiplicación es cero. Puede representar que todavía no se eligió ninguna unidad. Una cantidad negativa no tiene sentido en esta compra sencilla; una devolución sería otro caso, con reglas distintas. Más adelante distinguiremos entre calcular un resultado y validar si los datos son aceptables.
